# 출입구 등록 및 조회 기능 명세서

## 개요
SafeLight 애플리케이션의 출입구 등록 및 조회 시스템은 시각장애인이 건물의 정확한 출입구로 안내받을 수 있도록 지원하는 핵심 기능입니다. 사용자가 건물의 출입구 정보를 등록하고, 경로 탐색 시 등록된 출입구 정보를 활용하여 더 정확한 길안내를 제공합니다.

## 주요 기능

### 1. 출입구 등록 기능

#### 1.1 등록 프로세스
1. **위치 선택**: 네이버 맵에서 건물 위치 선택
2. **주소 자동 조회**: 카카오 API를 통한 도로명 주소 자동 획득
3. **정보 입력**:
   - 건물 이름 (필수)
   - 건물 상세정보 (선택)
   - 출입구 이름 (필수)
4. **서버 전송**: 입력된 데이터를 서버에 저장

#### 1.2 등록 데이터 구조
```dart
SendPointParams {
  roadAddress: String       // 도로명 주소
  buildingName: String      // 건물명
  buildingDetail: String?   // 건물 상세정보
  longitude: double         // 건물 경도
  latitude: double          // 건물 위도
  entrances: List<EntranceInfo>  // 출입구 목록
}

EntranceInfo {
  entranceName: String      // 출입구 이름 (정문, 후문 등)
  location: LatLng {        // 출입구 좌표
    longitude: double
    latitude: double
  }
}
```

### 2. 출입구 조회 기능

#### 2.1 조회 프로세스
1. **주소 기반 검색**: 도착지 주소로 건물 검색
2. **서버 요청**: 주소와 좌표로 출입구 정보 요청
3. **결과 표시**: 조회된 출입구 목록 표시
4. **선택**: 사용자가 원하는 출입구 선택

#### 2.2 조회 응답 데이터
```dart
BuildingResponse {
  buildingId: int           // 건물 ID
  buildingName: String      // 건물명
  buildingDetail: String    // 건물 상세정보
  entrances: List<Entrance> // 출입구 목록
}

Entrance {
  entranceName: String      // 출입구 이름
  location: LatLng          // 출입구 좌표
}
```

## 시스템 아키텍처

### 1. 계층 구조
```
Presentation Layer (View/Bloc)
    ↓
Domain Layer (UseCase)
    ↓
Data Layer (Repository)
    ↓
Data Source Layer (Remote API)
```

### 2. 주요 컴포넌트

#### 2.1 Presentation Layer

##### Views
- **EntranceRegistrationView**: 출입구 등록 화면
  - 네이버 맵 위젯
  - 건물 정보 입력 폼
  - 출입구 이름 입력 필드
  - 저장 버튼
  
- **EntranceSelectionView**: 출입구 선택 화면
  - 조회된 출입구 목록 표시
  - 출입구 선택 인터페이스

##### Blocs
- **EntranceRegistrationBloc**: 출입구 등록 상태 관리
  - States:
    - RegistrationInitial: 초기 상태
    - RegistrationLoading: 처리 중
    - RegistrationLoaded: 주소 로드 완료
    - EntranceSubmissionSuccess: 등록 성공
    - RegistrationFailure: 실패
  - Events:
    - AddressUpdated: 위치 변경
    - SubmitEntranceData: 데이터 제출

- **EntranceBloc**: 출입구 조회 상태 관리
  - States:
    - EntranceInitial: 초기 상태
    - EntranceLoading: 조회 중
    - EntranceLoaded: 조회 성공
    - EntranceError: 조회 실패
  - Events:
    - FetchBuildingEntrances: 출입구 조회 요청

#### 2.2 Domain Layer

##### UseCases
- **SendCustomStartPoint**: 출입구 등록 UseCase
  - 사용자 입력 데이터를 서버에 전송
  - Repository 호출하여 처리
  
- **GetBuildingEntrancesUseCase**: 출입구 조회 UseCase
  - 주소와 좌표로 출입구 정보 조회
  - 서버 응답을 엔티티로 변환

##### Entities
- **SendPointParams**: 출입구 등록 파라미터
- **EntranceInfo**: 개별 출입구 정보
- **BuildingResponse**: 건물 응답 정보
- **Entrance**: 출입구 엔티티

#### 2.3 Data Layer

##### Repository
- **NavigatorRepository** (인터페이스)
  - `sendCustomStartPointParams()`: 출입구 등록
  - `getBuildingEntrances()`: 출입구 조회
  - `getCurrentPosition()`: 현재 위치 조회

- **NavigatorRepositoryImpl**: Repository 구현체
  - UseCase와 DataSource 간 중개
  - 데이터 변환 및 에러 처리

##### Models
- **SendStartPointModel**: 등록 데이터 모델
  - Entity → JSON 변환
  
- **BuildingResponseModel**: 조회 응답 모델
  - JSON → Entity 변환
  - null 처리 및 기본값 설정
  
- **EntranceModel**: 출입구 모델
  - 위도/경도 값 스왑 처리 로직 포함
  - 한국 좌표 범위 검증 (위도: 33-38.5, 경도: 124-132)

#### 2.4 Data Source Layer

##### RemoteDataSource
- **NavigateRemoteDataSource** (인터페이스)
  - `sendCustomStartPoint()`: 서버에 등록 요청
  - `getBuildingEntrances()`: 서버에서 조회
  - `getCurrentLatLng()`: 현재 위치 획득

- **NavigateRemoteDataSourceImpl**: 구현체
  - Dio를 사용한 HTTP 통신
  - Geolocator를 사용한 위치 정보 획득
  - 상세한 디버그 로깅

## API 엔드포인트

### 1. 출입구 등록
- **URL**: `http://aws2.cuksl.xyz:3003/save/entrances`
- **Method**: POST
- **Request Body**:
```json
{
  "roadAddress": "도로명 주소",
  "buildingName": "건물명",
  "buildingDetail": "건물 상세",
  "buildingPoint": {
    "lon": 126.8018,
    "lat": 37.4865
  },
  "entrances": [
    {
      "entranceName": "정문",
      "lon": 126.8018,
      "lat": 37.4865
    }
  ]
}
```

### 2. 출입구 조회
- **URL**: `http://aws2.cuksl.xyz:3003/{encodedAddr}/{longitude}/{latitude}`
- **Method**: GET
- **Response**:
```json
{
  "bldg_id": 1,
  "building_name": "건물명",
  "building_detail": "상세정보",
  "entrances": [
    {
      "entranceName": "정문",
      "lon": 126.8018,
      "lat": 37.4865
    }
  ],
  "exit_count": 2
}
```

## 사용자 경험

### 1. 출입구 등록 화면
1. **지도 영역** (상단 50%)
   - 네이버 맵 표시
   - 중앙 고정 마커 (빨간색 위치 핀)
   - 상단 주소 표시 바
   - 현재 위치 버튼

2. **입력 폼 영역** (하단 50%)
   - 건물 이름 입력 필드
   - 건물 상세정보 입력 필드
   - 출입구 이름 입력 필드
   - 저장 버튼

### 2. 출입구 선택 화면
- 건물명 표시
- 출입구 목록 카드 형태로 표시
- 탭하여 선택 가능

### 3. 피드백 메시지
- **등록 성공**: "출입구 정보가 저장되었습니다"
- **등록 실패**: 에러 타입별 메시지
- **조회 실패**: "Failed to fetch entrances"
- **출입구 없음**: "No entrances found"

## 데이터 검증 및 처리

### 1. 입력 검증
- 출입구 이름 필수 입력
- 위치 선택 필수
- 건물명 필수 입력
- 빈 문자열 trim 처리

### 2. 좌표 처리
- **위도/경도 스왑 감지**: 서버 응답 값이 뒤바뀐 경우 자동 교정
- **한국 좌표 범위 검증**:
  - 위도: 33.0 ~ 39.0
  - 경도: 120.0 ~ 135.0
- **휴리스틱 기반 자동 교정**

### 3. Null 처리
- 서버 null 응답 → 기본값 설정
- buildingId null → -1
- buildingName null → "데이터 없음"
- buildingDetail null → "정보 없음"
- entrances null → 빈 리스트

## 에러 처리

### 1. 네트워크 에러
- **ServerException**: 서버 통신 실패
- **DioException**: HTTP 요청 실패
- 상세한 에러 로깅 (상태 코드, 응답 데이터)

### 2. 위치 에러
- Geolocator 실패 → ServerException
- 주소 변환 실패 → "주소를 찾을 수 없습니다"

### 3. 데이터 에러
- JSON 파싱 실패 처리
- 타입 캐스팅 안전 처리
- null safety 보장

## 문제 해결 가이드

### 출입구가 조회되지 않을 때
1. 건물 주소가 정확한지 확인
2. 서버 연결 상태 확인
3. 좌표 값이 올바른지 확인

### 등록이 실패할 때
1. 모든 필수 필드 입력 확인
2. 네트워크 연결 확인
3. 서버 상태 확인

### 위치가 부정확할 때
1. GPS 권한 확인
2. 실내/실외 환경 확인
3. 지도 캐시 초기화
