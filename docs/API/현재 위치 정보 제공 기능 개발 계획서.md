# 현재 위치 정보 제공 기능 개발 계획서

## 1. 개요

### 1.1 목적
사용자가 버튼을 누르면 GPS 좌표를 기반으로 가장 가까운 건물 정보를 조회하고 TTS로 음성 안내하는 기능 구현

### 1.2 핵심 전략
**기존 출입구 조회 API를 재사용하여 개발 시간 단축 및 안정성 확보**

---

## 2. 기술적 배경

### 2.1 API 현황 분석

#### 원래 기획
```
GET /location/{lon}/{lat}
- GPS 좌표만으로 건물 정보 조회
- 서버가 자동으로 city 판별
```

#### 실제 서버 상태
```
❌ /location/{lon}/{lat} → 400 Bad Request
✅ /{city}/{lon}/{lat} → 200 OK

문제: 서버에 /location 엔드포인트가 구현되지 않음
해결: 기존 출입구 조회 API 재사용
```

### 2.2 선택한 해결 방안

**출입구 조회 API 재사용 + 역지오코딩**

```
GPS 좌표 (lat, lon)
    ↓
역지오코딩 (geolocator)
    ↓
주소 ("경기도 수원시 영통구")
    ↓
출입구 조회 API: /{city}/{lon}/{lat}
    ↓
BuildingResponse (buildingName, buildingDetail)
    ↓
TTS 음성 안내
```

## 4. 구현 계획

### Phase 1: GeocodingService 생성 (NEW)

**파일:** `lib/data/services/geocoding_service.dart`

**기능:**
- GPS 좌표 → 주소 문자열 변환
- geolocator 패키지의 `placemarkFromCoordinates()` 활용
- 한국어 로케일 설정 (`ko_KR`)

**반환 형식:**
```dart
"경기도 수원시 영통구 원천동"
// 시/도 + 시/군/구 + 읍/면/동 + 도로명
```

**에러 처리:**
- 네트워크 실패 → "알 수 없는 위치"
- Placemark 없음 → "알 수 없는 위치"
- 권한 없음 → "알 수 없는 위치"

---

### Phase 2: Controller 리팩토링

**파일:** `lib/presentation/controllers/location_announcement_controller.dart`

**변경 사항:**

| Before | After | 사유 |
|--------|-------|------|
| LocationRepository | NavigatorRepository | 출입구 API 재사용 |
| - | GeocodingService | 역지오코딩 필요 |
| LocationInfo | BuildingResponse | Entity 통합 |

**새로운 로직:**
```dart
Future<void> announceNearbyBuilding() async {
  // 1. GPS 좌표
  final position = await navigatorRepository.getCurrentPosition();

  // 2. 역지오코딩
  final address = await geocodingService.getAddressFromCoordinates(
    latitude: position.latitude,
    longitude: position.longitude,
  );

  // 3. 출입구 API 호출
  final result = await navigatorRepository.getBuildingEntrances(
    encodedAddr: Uri.encodeComponent(address),
    longitude: position.longitude,
    latitude: position.latitude,
  );

  // 4. TTS 안내
  result.fold(
    (failure) => ttsService.speak('주변 건물 정보를 가져올 수 없습니다'),
    (building) => ttsService.speak(_buildTtsMessage(building)),
  );
}
```

**TTS 메시지 생성:**
```dart
String _buildTtsMessage(BuildingResponse building) {
  if (building.buildingName == null) {
    return '현재 위치는 건물 정보가 없는 지역입니다';
  }

  final parts = [building.buildingName!];
  if (building.buildingDetail != null &&
      building.buildingDetail!.isNotEmpty) {
    parts.add(building.buildingDetail!);
  }

  return '${parts.join(' ')}입니다';
}
```

## 6. 테스트 시나리오

### 6.1 정상 케이스

**Case 1: 건물 내부**
```
입력: GPS (126.8015, 37.4859)
역지오코딩: "경기도 수원시 영통구 원천동"
API 응답: {
  "buildingName": "아주대학교",
  "buildingDetail": "다산관"
}
TTS: "아주대학교 다산관입니다"
```

**Case 2: 건물 상세 정보 없음**
```
입력: GPS (127.0276, 37.4979)
역지오코딩: "서울특별시 강남구 역삼동"
API 응답: {
  "buildingName": "강남역",
  "buildingDetail": null
}
TTS: "강남역입니다"
```

### 6.2 에러 케이스

**Case 3: GPS 실패**
```
NavigatorRepository.getCurrentPosition() → Failure
TTS: "GPS 정보를 가져올 수 없습니다"
```

**Case 4: 역지오코딩 실패**
```
GeocodingService.getAddressFromCoordinates() → "알 수 없는 위치"
API 호출 진행 (실패 가능성 높음)
```

**Case 5: API 실패**
```
NavigatorRepository.getBuildingEntrances() → ServerFailure
TTS: "주변 건물 정보를 가져올 수 없습니다"
```

**Case 6: 건물 정보 없음**
```
API 응답: { "buildingName": null }
TTS: "현재 위치는 건물 정보가 없는 지역입니다"
```

## 7. 위험 요소 및 대응

### 7.1 역지오코딩 정확도
**위험:** GPS 좌표가 경계선에 있을 경우 잘못된 city 반환

**대응:**
- Placemark의 administrativeArea 사용 (시/도)
- 서버에서 Haversine 거리 계산으로 보정

### 7.2 네트워크 지연
**위험:** 역지오코딩 + API 호출 = 2번의 네트워크 요청

**대응:**
- 로딩 상태 표시 (_isLoading)
- 타임아웃 설정 (Dio)
- 사용자 피드백 (TTS)

### 7.3 권한 문제
**위험:** 위치 권한 거부

**대응:**
- NavigatorRepository에서 이미 처리됨
- Either 패턴으로 에러 전달
- TTS로 사용자 안내

## 10. 향후 개선 방안

### 10.1 서버 측 개선 (권장)
```
서버 팀에 /location/{lon}/{lat} 엔드포인트 구현 요청
→ 클라이언트에서 역지오코딩 불필요
→ 네트워크 요청 1회로 감소
```

### 10.2 캐싱 전략
```
최근 조회한 위치 캐싱
→ 동일 위치 재조회 시 즉시 응답
→ 네트워크 요청 감소
```

### 10.3 오프라인 지원
```
로컬 DB에 주요 건물 정보 저장
→ 네트워크 없어도 기본 정보 제공
```
