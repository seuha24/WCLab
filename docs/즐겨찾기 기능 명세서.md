# 즐겨찾기 기능 명세서

## 개요
SafeLight 애플리케이션의 즐겨찾기 시스템은 사용자가 자주 방문하는 지점과 경로를 저장하여 빠르게 접근할 수 있도록 돕는 핵심 기능입니다. 로그인한 사용자의 데이터는 서버에 동기화되어 기기 변경 시에도 유지되며, 지점 즐겨찾기와 경로 즐겨찾기 두 가지 유형을 제공합니다.

## 주요 기능

### 1. 즐겨찾기 지점 (Favorite Points)

#### 1.1 지점 등록 기능
- **장소 검색**: 카카오 장소 검색 API 활용
- **출입구 연동**: 등록된 출입구 정보 자동 연결
- **좌표 저장**: 건물 좌표와 출입구 좌표 분리 저장
- **커스텀 이름**: 사용자가 원하는 이름으로 저장

#### 1.2 지점 데이터 구조
```dart
class FavoritePoint {
  String name;                  // 사용자 지정 이름
  double longitude;             // 건물 경도
  double latitude;              // 건물 위도
  double? entranceLongitude;    // 출입구 경도 (선택)
  double? entranceLatitude;     // 출입구 위도 (선택)
}
```

#### 1.3 사용 시나리오
1. 자주 가는 장소 저장 (집, 회사, 학교 등)
2. 빠른 목적지 설정
3. 출입구 정보 포함한 정확한 안내

### 2. 즐겨찾기 경로 (Favorite Routes)

#### 2.1 경로 등록 기능
- **출발지 설정**: 검색 또는 지도 선택
- **목적지 설정**: 검색 또는 지도 선택
- **경유지 지원**: 최대 3개 경유지 추가 가능
- **출입구 정보**: 각 지점별 출입구 선택 가능

#### 2.2 경로 데이터 구조
```dart
class FavoriteRoute {
  String name;                  // 경로 이름
  RoutePoint? startPoint;       // 출발지
  RoutePoint? finishPoint;      // 목적지
  List<RoutePoint?> stopovers;  // 경유지 목록 (최대 3개)
}

class RoutePoint {
  double longitude;             // 경도
  double latitude;              // 위도
}
```

#### 2.3 사용 시나리오
1. 일상 경로 저장 (출퇴근, 등하교)
2. 복잡한 경로 저장 (경유지 포함)
3. 자주 사용하는 경로 템플릿

## 시스템 아키텍처

### 1. 계층 구조
```
Presentation Layer (View)
    ↓
Domain Layer (UseCase)
    ↓
Data Layer (Repository)
    ↓
Data Source Layer (Remote API)
```

### 2. 주요 컴포넌트

#### 2.1 Presentation Layer

##### Views
- **FavoritesMainView**: 즐겨찾기 메인 화면
  - TabBar로 지점/경로 구분
  - 목록 표시 및 관리
  - FloatingActionButton으로 추가
  
- **FavoritePointAddView**: 지점 추가 화면
  - 장소 검색 (StartSearch 연동)
  - 출입구 선택 (EntranceSelectionView 연동)
  - 이름 입력 및 저장
  
- **FavoriteRouteAddView**: 경로 추가 화면
  - 출발지/목적지/경유지 선택
  - 각 지점별 출입구 선택
  - 경로 이름 입력 및 저장

##### 상태 관리
- **TabController**: 지점/경로 탭 전환
- **로딩 상태**: CircularProgressIndicator 표시
- **에러 처리**: 에러 메시지 및 재시도 버튼

#### 2.2 Domain Layer

##### UseCases
- **GetFavoritePoints**: 지점 목록 조회
  - 파라미터: loginMethod, userId
  - 반환: List<FavoritePoint>
  
- **GetFavoriteRoutes**: 경로 목록 조회
  - 파라미터: loginMethod, userId
  - 반환: List<FavoriteRoute>
  
- **AddFavoritePoint**: 지점 추가
  - 파라미터: loginMethod, userId, name, longitude, latitude
  - 반환: FavoritePoint
  
- **AddFavoriteRoute**: 경로 추가
  - 파라미터: loginMethod, userId, name, startPoint, finishPoint, stopovers
  - 반환: bool (성공 여부)

##### Entities
- **FavoritePoint**: 지점 엔티티
- **FavoriteRoute**: 경로 엔티티
- **RoutePoint**: 경로 지점 엔티티

#### 2.3 Data Layer

##### Repository
- **FavoriteRepository** (인터페이스)
  - `getFavoritePoints()`: 지점 목록 조회
  - `getFavoriteRoutes()`: 경로 목록 조회
  - `addFavoritePoint()`: 지점 추가
  - `addFavoriteRoute()`: 경로 추가

- **FavoriteRepositoryImpl**: Repository 구현체
  - Either 패턴으로 에러 처리
  - Model → Entity 변환

##### Models
- **FavoritePointModel**: 지점 데이터 모델
  - JSON ↔ Model 변환
  - toEntity() 메서드
  
- **FavoriteRouteModel**: 경로 데이터 모델
  - JSON ↔ Model 변환
  - toEntity() 메서드
  
- **RoutePointModel**: 경로 지점 모델
  - lon/lat 필드 매핑

#### 2.4 Data Source Layer

##### RemoteDataSource
- **FavoriteRemoteDataSource** (인터페이스)
  - 서버 API 통신 정의

- **FavoriteRemoteDataSourceImpl**: 구현체
  - Dio 클라이언트 사용
  - 상세한 디버그 로깅
  - 에러 처리 (ServerException)

## API 엔드포인트

### 1. 서버 정보
- **Base URL**: `http://aws2.cuksl.xyz:3003`
- **인증**: loginMethod (google/apple) + userId (서버 UUID)

### 2. 지점 관련 API

#### 2.1 지점 조회
- **GET** `/fav_point/{loginMethod}/{userId}`
- **Response**:
```json
{
  "login_method": "google",
  "ID": "userID",
  "list": [
    {
      "name": "우리집",
      "lon": 126.8015,
      "lat": 37.4859,
      "entrance_lon": 126.8016,
      "entrance_lat": 37.4860
    }
  ]
}
```

#### 2.2 지점 추가
- **POST** `/save/fav/point`
- **Request**:
```json
{
  "login_method": "google",
  "ID": "userID",
  "new_fav_point": {
    "name": "새로운 장소",
    "lon": 126.8015,
    "lat": 37.4859
  }
}
```

### 3. 경로 관련 API

#### 3.1 경로 조회
- **GET** `/fav_route/{loginMethod}/{userId}`
- **Response**:
```json
{
  "login_method": "google",
  "ID": "userID",
  "list": [
    {
      "name": "출퇴근 경로",
      "start_point": {"lon": 126.8015, "lat": 37.4859},
      "finish_point": {"lon": 126.8020, "lat": 37.4870},
      "stopovers": [
        {"lon": 126.8017, "lat": 37.4865}
      ]
    }
  ]
}
```

#### 3.2 경로 추가
- **POST** `/save/fav/route`
- **Request**:
```json
{
  "login_method": "google",
  "ID": "userID",
  "list": {
    "name": "새 경로",
    "start_point": {"lon": 126.8015, "lat": 37.4859},
    "finish_point": {"lon": 126.8020, "lat": 37.4870},
    "stopovers": [null, null, null]
  }
}
```

## 인증 및 사용자 관리

### 1. 사용자 식별
- **Firebase Auth**: 사용자 인증
- **AuthType**: google/apple/anonymous 구분
- **서버 UUID**: `/user/me` API로 획득
- **AuthService**: 토큰 및 사용자 정보 관리

### 2. 인증 플로우
1. Firebase 로그인 확인
2. AuthType 확인 (google/apple)
3. 서버 UUID 조회
4. 즐겨찾기 API 호출

### 3. 익명 사용자 처리
- 익명 로그인 시 즐겨찾기 비활성화
- "로그인이 필요합니다" 메시지 표시

## 출입구 연동

### 1. 자동 연동 프로세스
1. 장소 검색 (카카오 API)
2. 건물 출입구 조회 (서버 API)
3. 출입구 선택 화면 표시
4. 선택된 출입구 좌표 저장

### 2. 출입구 없는 경우
- 카카오 API 좌표 그대로 사용
- entranceLongitude/Latitude는 null

### 3. 출입구 조회 실패
- 에러 무시하고 카카오 좌표 사용
- 사용자 경험 우선

## 성능 최적화

### 1. 캐싱
- 조회된 데이터 메모리 캐싱
- 화면 전환 시 재조회 방지

### 2. 로딩 최적화
- 지점/경로 병렬 조회
- 실패 시에도 부분 표시

### 3. 디버깅
- 상세한 요청/응답 로깅
- JSON 데이터 포맷팅 출력

## 에러 처리

### 1. 네트워크 에러
- ServerException 발생
- "오류가 발생했습니다" 표시
- 재시도 버튼 제공

### 2. 인증 에러
- "로그인이 필요합니다" 표시
- 로그인 화면 유도

### 3. 데이터 에러
- 빈 리스트 반환
- null 안전 처리
- 기본값 제공

## 문제 해결 가이드

### 즐겨찾기가 표시되지 않을 때
1. 로그인 상태 확인
2. 네트워크 연결 확인
3. 서버 상태 확인
4. 새로고침 시도

### 추가가 실패할 때
1. 필수 입력 확인
2. 네트워크 상태 확인
3. 로그인 상태 확인

### 출입구가 연동되지 않을 때
1. 건물 출입구 등록 여부 확인
2. 서버 API 상태 확인
3. 수동으로 출입구 등록

## 보안 고려사항

### 1. 데이터 보호
- 서버 통신 HTTPS 필요 (현재 HTTP)
- 사용자별 데이터 격리
- UUID 기반 사용자 식별

### 2. 권한 검증
- 로그인 사용자만 접근
- loginMethod + userId 검증

## 참고 사항
- 즐겨찾기는 로그인 사용자 전용 기능
- 익명 사용자는 사용 불가
- 기기 변경 시 동일 계정으로 동기화
- 최대 저장 개수 제한 없음 (서버 정책에 따름)
